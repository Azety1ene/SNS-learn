# ADR-0004: 開発の進め方

- 状態: 承認
- 日付: 2026-10-23

## 背景

- オーナーはスマホからしか操作しない。コマンドの実行や、手元での動作確認はできない
- 最大の目的は学習。変更ごとに「何を・なぜ」を理解しながら進めたい
- Claude の作業環境（クラウド上のコンテナ）は時間が経つと消え、セッションは毎回まっさらな状態から始まる
- Vercel の無料プランは、private リポジトリの場合、Vercel アカウントの持ち主が作ったコミットしかデプロイしない

## 決定

- 1 ステップ ＝ 1 つの PR で進める。ステップの順番は `docs/ROADMAP.md` に従う
- Claude は main から作業ブランチを作って実装し、テストを通してから PR を作る。main へ直接 push しない（リポジトリを作った直後の、中身のない初期コミットだけは例外）
- PR には「何を・なぜ・学びポイント・スマホでの確認手順」を書き、学習ノート（`docs/learning/`）を添える
- GitHub Actions がテストし、Vercel が PR ごとのプレビュー環境を作る
- オーナーはスマホでプレビューを触り、GitHub アプリでコードを読み、分からない行にコメントで質問する
- マージはオーナーが行う。main にマージされたら、Vercel が本番に反映する
- リポジトリは public にする

## 理由

- PR を小さく保てば、スマホでも全体を読み切れる
- プレビュー環境があれば、マージ前に本物の環境で動作を確かめられる
- public にすると、Vercel の無料プランでも Claude のコミットをデプロイでき、GitHub Actions を時間無制限で使え、main のブランチ保護も設定できる
- 進捗・判断・学びをリポジトリに残すことで、セッションが変わっても続きから作業できる

## 影響

良い点

- ステップごとの解説（学習ノート）が、教科書のようにたまっていく
- すべての変更が、テストとレビューを経てから本番に入る

注意点

- public なので、秘密情報は絶対にコミットしない。API キーなどは Vercel や GitHub の設定画面に直接登録する
- オーナーが外部サービスを設定する場面（アカウント登録、OAuth アプリの登録など）では、Claude が画面の名前まで具体的に手順を案内する
