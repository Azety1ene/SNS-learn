# ADR-0006: 進め方の見直し（マイルストーンごとの PR・学ぶ内容の絞り込み）

- 状態: 承認（ADR-0004 の「1 ステップ ＝ 1 PR」を置き換える）
- 日付: 2026-10-23

## 背景

- ADR-0004 では、1 ステップ ＝ 1 つの PR（全 65 ステップ）で進める予定だった
- オーナーから、次のフィードバックがあった
  - コードを読まないと学習が始まらない。PR が多すぎると途中で投げ出してしまう
  - 学ぶ内容が多すぎると、かえって分かりにくい

## 決定

- PR は「まとまった機能（マイルストーン）」ごとに 1 本にする（M1〜M4 と、任意の発展機能）
- 学ぶテーマを絞る
  - メイン: Next.js の「サーバーとブラウザの分担」（Server Components／Client Components／Server Actions）
  - サブ: DB のテーブル設計とクエリ
- PR には「まず読むファイル（5 つ程度）」と「読まなくてよいファイル」を書く
- 学習ノートはマイルストーンごとに 1 本、要点は 3 つまでにする
- 品質は落とさない。テスト・CI・セキュリティ対策は今までどおり入れるが、オーナーに読むことは求めない
- ADR-0004 のそれ以外の決定（public リポジトリ、マージはオーナーが行う、プレビュー環境、秘密情報の扱い）は引き続き有効

## 理由

- 早く「動くもの」と「読めるコード」が手に入るほうが、学習を続けやすい
- 読む場所を絞ると、大きな PR でも迷わずに読める

## 影響

良い点

- 早く動くものができる
- 読む量が減り、大事なところに集中できる

注意点

- 1 つの PR が大きくなる。「まず読むファイル」で道案内をする
- 問題が起きたときに原因を絞り込みにくくなる。自動テストで補う
