# ADR-0009: Google ログインとパスキーを追加し、外部アカウントの連携の決まりを定める

- 状態: 承認
- 日付: 2026-10-24

## 背景

- ADR-0003 で、Google・GitHub の OAuth でログインし、ログイン後にパスキーを追加できるようにすると決めた
- 1 人が複数のログイン方法を持つようになるので、「どのアカウントを同じ人とみなすか（連携）」と「どこまで解除できるか」を決める必要がある
- Google の設定はオーナーがスマホで行う。設定が終わるまでの間も、サイトは動き続ける必要がある
- パスキーは 1 つのドメインに結びつく。プレビュー環境には URL が 2 種類ある（デプロイごとの URL と、ブランチごとの URL）

## 決定

1. **Google でのログイン**: 環境変数（`GOOGLE_CLIENT_ID`・`GOOGLE_CLIENT_SECRET`）が設定されているときだけ有効にし、ボタンを表示する
2. **自動の連携**: ログイン画面から別の方法でログインし、同じメールアドレスのユーザーがすでにいたときは、両方のメールアドレスが確認済みの場合だけ自動で連携する（Better Auth の初期設定のまま）。それ以外は断り、「前回と同じ方法でログインしてから、設定画面で連携して」と案内する
3. **設定画面からの連携**: ログイン中の本人が行う。メールアドレスが違うアカウントも連携できる（`allowDifferentEmails`）
4. **連携の解除**: 外部アカウント（GitHub・Google）が 1 つだけのときは解除できない。パスキーがあっても同じ。同時に解除が届いたときに備えて、ユーザーの行をロックしてから確かめる（`SELECT ... FOR UPDATE`）
5. **パスキー**: Better Auth のパスキーのプラグインを使う
   - 登録はログイン中だけ。パスキーだけで新規登録はできない
   - 結びつけるドメイン（rpID）は環境ごとに明示する（本番は本番のドメイン、プレビューはブランチごとの URL、ローカルは localhost）
   - 端末にパスキーを保存してもらう設定（`residentKey: "required"`）にして、ID を入力せずにログインできるようにする
   - 一覧と削除は、このアプリの処理（クエリと Server Action）で行う。プラグインの同じ機能の入口（一覧・削除・名前の変更）は無効にする
6. **投稿の共有ボタン**（オーナーの要望）: スマホでは OS の共有メニューを開き、ないブラウザではリンクをコピーする

## 理由

- **Google を任意にする**: 設定が終わる前でも、パスキーなどほかの機能をプレビューで試せる。設定し忘れは、ボタンが出ないことで気づける
- **自動の連携を「両方とも確認済み」に限る**: 他人のメールアドレスで先にアカウントを作っておき、あとで本人が Google でログインしたときに自分のアカウントへ連携させて乗っ取る攻撃（事前の乗っ取り）を防ぐ。確認済みのメールアドレスなら、そのアドレスの持ち主が作ったアカウントだと分かる
- **設定画面ではメールアドレスの違いを許す**: 本人が両方のアカウントで実際にログインして確かめるので、なりすましの余地がない。GitHub と Google でメールアドレスが違う人は多い
- **外部アカウントを 1 つは残す**: パスキーだけになると、パスキーを保存した端末をなくしたとき、新しい端末からログインする方法がなくなる
- **行のロック**: ロックなしで GitHub と Google の解除を同時に送ると、5 回中 3 回、両方とも解除されて連携が 0 件になった（学習ノート 04 の 4 章）。ロックすれば毎回片方だけになる
- **rpID を明示する**: プラグインは、プレビューのように URL を 1 つに決めていない設定だと rpID を `localhost` にしてしまい、パスキーが使えない。ブランチごとの URL は PR のコメントに表示され、同じ PR の間は変わらないので、こちらに決める
- **一覧と削除を自前の処理にする**: 「読み取り（queries）・書き込み（mutations）・Server Actions」というこのアプリの書き方にそろえ、本物の DB でテストしやすくするため。登録とログインは暗号の処理なので、ライブラリに任せる
- **共有ボタン**: 「投稿のリンクが見つからない」という声があった。リンクのプレビュー（OGP、M2）も、このボタンから試せる

## 影響

良い点

- GitHub・Google・パスキーのどれでも同じアカウントにログインできる
- パスキーは偽サイトでは使えず、サーバーには公開鍵しかないので、漏れても悪用できない

注意点

- サーバーは、パスキーでログインするときに「指紋や顔で本人確認したか」までは確かめない（ライブラリがそう作られている）。スマホのパスキーは常に本人確認を行うので、実際の影響は小さい
- プレビューでパスキーを試すときは、ブランチごとの URL（PR のコメントに出る URL）を使う。デプロイごとの URL では使えない
- プレビュー環境の OAuth は本番を経由する（ADR-0003）ので、Google でのログインは、M3 が本番に入るまでプレビューでは試せない
- サーバーでパスキーを削除しても、端末に保存されたパスキーは残る。端末の設定から削除してもらう
- Google のログインは「テスト中」の間、テストユーザーに登録した人しか使えない。一般公開の前（M4）に「本番環境」へ切り替える
- アカウントの削除（M4）では、連携とパスキーも消える（外部キーの ON DELETE CASCADE）
