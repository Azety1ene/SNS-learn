# 要件定義

最終更新: 2026-10-23（フェーズ0）

「（仮）」が付いた数値は、実装しながら調整します。

## 1. 目的

- オーナーが、Web アプリを設計・実装・テスト・デプロイ・運用する一連の流れを学ぶ
- 学習用でも品質は落とさない。モックやダミー実装は使わず、本番で運用できるものを作る
- 無料枠だけで運用する（カード登録なし）

## 2. 学習方針

- 学ぶ人: 実務経験あり。Next.js を勉強中
- 学び方: Claude が書いたコード・PR・学習ノートを読んで理解する。疑問は PR のコメントかチャットで質問する
- 重点を置くこと
  - Next.js（App Router、Server Components、Server Actions、キャッシュ）
  - DB 設計と SQL
  - 認証とセキュリティ
  - 自動テストと CI/CD
  - 運用（監視、障害対応、無料枠の管理）
- 作業環境: オーナーはスマホのみ。実装・テスト・デプロイはクラウド上で完結させる

## 3. サービスの概要

- X（旧Twitter）のような、テキスト中心の SNS
- 誰でも登録できる（Google か GitHub のアカウントが必要）
- 想定する規模: 登録者は数百人まで、同時に使うのは数十人程度
- サービス名: 未定（決まったら URL にも使う）

## 4. 機能要件

### 4.1 最初のリリース（MVP）に入れる機能

**アカウント**

- Google または GitHub のアカウントで登録・ログインできる
- ログイン後にパスキーを追加でき、以降はパスキーでもログインできる
- 初回登録時に、ユーザー ID（@id）と表示名を決め、利用規約に同意する
- ログアウトできる
- アカウントを削除できる（本人のデータも消える）

**プロフィール**

- 表示名、自己紹介、アイコン画像、登録日、フォロー数・フォロワー数を表示する
- 自分のプロフィールを編集できる

**投稿**

- テキスト（最大 280 文字（仮））と画像（最大 4 枚）を投稿できる
- 自分の投稿を削除できる
- 投稿の詳細ページを見られる
- 投稿に返信でき、スレッドとして表示される
- 投稿に「いいね」できる
- 投稿のリンクを SNS やチャットに貼ると、内容のプレビューが表示される（OGP）

**フォローとタイムライン**

- 他のユーザーをフォロー・解除できる。フォロー中・フォロワーの一覧を見られる
- ホームタイムライン: 自分とフォロー中の人の投稿
- 全体タイムライン: 全ユーザーの投稿
- どちらも新しい順で、下までスクロールすると続きを読み込む

**安全のための機能**（誰でも登録できるため、最初から入れる）

- ブロック: お互いの投稿が見えなくなり、相手からの返信やフォローもできなくなる
- ミュート: 相手の投稿が自分のタイムラインに出なくなる（相手には伝わらない）
- 通報: 投稿やユーザーを管理者に通報できる
- 管理者: 通報を確認し、投稿の削除やアカウントの停止ができる
- 回数制限: 投稿・いいね・フォロー・通報などの、短時間の連続操作を制限する
- 画像アップロードの上限: 1 人あたりとサービス全体の両方で上限を設ける（6 章）

**その他**

- 利用規約、プライバシーポリシー、問い合わせ窓口
- エラーページ（ページが見つからない、など）

### 4.2 MVP の後に追加する機能

- 通知（いいね・フォロー・返信）
- 検索（ユーザーと投稿）
- リアルタイム更新
- PWA（ホーム画面に追加）とプッシュ通知
- リポストと引用
- ハッシュタグとメンション
- ブックマーク
- データのエクスポート

### 4.3 作らないもの

| 機能 | 理由 |
| --- | --- |
| DM（個人間のメッセージ） | 日本では電気通信事業法の届出が関係する場合があるため |
| パスワードでのログイン | 安全性と無料枠の都合（ADR-0003） |
| メール送信 | 確実に届けるには独自ドメイン（有料）が必要なため |
| 動画の投稿 | 保存容量が無料枠に収まらないため |
| 広告・有料機能 | Vercel の無料プランは非商用に限られるため |
| ネイティブアプリ | PWA で代用するため |

## 5. 非機能要件

**対応環境**

- スマホを最優先（iPhone の Safari、Android の Chrome の最新版）
- PC のブラウザ（Chrome、Safari、Edge、Firefox の最新版）でも崩れずに使える

**言語と時刻**

- 画面は日本語
- 日時は日本時間で表示する

**性能（目安）**

- 主な画面は 2 秒以内に表示される（DB の休止明けの初回アクセスは除く）

**可用性**

- 無料枠のため、稼働の保証はしない
- DB の休止明けに数秒待たされることは許容する

**セキュリティ**

- パスワードを保存しない（ADR-0003）
- 通信はすべて HTTPS にする
- ログイン状態の Cookie は、JavaScript から読めない（HttpOnly）、HTTPS でのみ送られる（Secure）、他のサイトからのリクエストには付かない（SameSite）設定にする
- 入力チェックと権限チェックは必ずサーバー側で行う
- XSS、CSRF、SQL インジェクションの対策をする
- 秘密情報はコードに含めない

**プライバシー**

- 受け取る個人情報は最小限にする（Google/GitHub から受け取る名前・メールアドレス・アイコン）。メールアドレスは公開しない
- 画像の位置情報（Exif）は保存する前に取り除く
- アカウントを削除したら、本人のデータを消す

**アクセシビリティ**

- キーボードで操作できる
- 文字と背景のコントラストを十分にとる
- 画像に代替テキストを付けられる

**品質**

- 型チェック・Lint・自動テストが CI で通ること
- 自動テストは本物の DB で行う（ADR-0005）

## 6. 制約（無料枠）

2026 年 10 月時点の公式情報です。条件は変わることがあるので、関係するステップで改めて確認します。

| サービス | 主な上限 |
| --- | --- |
| Vercel（Hobby） | 月あたり: 関数の実行 100 万回、CPU 時間 4 時間、転送量 100GB、画像最適化 5,000 回 |
| Vercel Blob | 保存 1GB。月あたり: アップロード等 2,000 回、転送量 10GB |
| Neon（Free） | 保存 0.5GB、DB ブランチ 10 個。月あたり計算 100CU 時間 |
| GitHub Actions | public リポジトリは無制限 |

- 上限を超えても課金はされず、止まるだけ（Vercel は最大 30 日、Neon は翌月まで）
- Vercel の無料プランは非商用の利用に限られる

### 無料枠を守るための方針（仮）

- 画像は、アップロード前にブラウザで長辺 1600px の JPEG に縮小し（1 枚 1MB まで）、サーバーで WebP に変換する（1 枚あたり数百 KB）
- 1 人あたりの画像アップロードは 24 時間で 10 枚まで（アイコンも含む）
- サービス全体で、画像の合計容量が 800MB、または直近 31 日のアップロード数が 1,600 枚（どちらも無料枠の 8 割）に達したら、新しいアップロードを止める（[ADR-0008](adr/0008-image-storage.md)）
- テキストの投稿は、DB の 0.5GB で数十万件程度まで保存できる見込み
